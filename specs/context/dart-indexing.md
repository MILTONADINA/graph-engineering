# Dart syntax indexing

- ID: dart-indexing
- Status: ready
- Area: context

## Problem

Dart and Flutter repositories need bounded, source-backed context: declarations to search, imports and calls to follow, and honest coverage when something could not be read. The pinned tree-sitter grammar already includes Dart, but its tree differs from the others: a function's signature and body are sibling nodes, calls are selector chains rather than call expressions, and named constructors carry several names. The generic extractor would credit every function body to its file and miss the calls. Dart syntax support must not change repositories without Dart files. A separately provisioned, pinned analyzer may add only narrow declaration bindings inside an isolated source-only view; its native Linux Docker test remains a required exact-head CI gate, not a local Mac result.

## Acceptance criteria

- AC1: Indexing a Dart package records its top-level functions, classes, named and factory constructors, static and instance methods, getters and extensions, pairing each signature with the body that follows it; its imports (prefixed or not), exports and part directives as unresolved import edges; and calls read from selector chains and cascades, credited to the declaration whose body holds them. A bare call is linked, as a heuristic lexical candidate, only to the one declaration of that name in the same file, when that declaration is a top-level or local function that no parameter, variable, field, loop, catch or pattern binding in the file could shadow; every other call, such as a member call, a call through a prefixed import, a call to a function in another file of the library or a constructor call, stays unresolved.
  - Test: packages/engine/tests/context-dart.test.ts :: indexes Dart declarations, imports and selector calls from the toy package
- AC2: Valid Dart that the pinned grammar cannot parse, such as an unnamed `library;`, null-aware elements, dot shorthands and labeled statements, is reported as the `syntax errors; graph may be incomplete` coverage diagnostic for exactly the file that holds it; the file's declarations are kept as partial evidence, and it links no calls.
  - Test: packages/engine/tests/context-dart.test.ts :: reports Dart syntax the pinned grammar cannot parse as incomplete coverage
- AC3: The optional analyzer accepts only hash-checked snapshot Dart text under bounded, safe paths, derives only a validated root package name from an indexed manifest whose source identity is retained, and never materializes repository configuration, plugins or dependencies. It requires the reviewed Linux x64 image and checked seccomp profile; host Dart and caller-supplied runtime identities are not fallbacks.
  - Test: packages/engine/tests/context-dart-snapshot.test.ts :: prepares only bounded Dart source, with eligible calls and declarations
  - Test: packages/engine/tests/context-dart-snapshot.test.ts :: rejects source aliases, executable configuration and untrusted metadata
  - Test: packages/engine/tests/context-dart-runtime.test.ts :: does not accept a caller-provided runtime or execute any host Dart wrapper
- AC4: A unique analyzer answer may promote only an exact source-backed top-level function, class static method or constructor target. A `Location` must match one exact eligible target name; a `LocationLink` must additionally match the query origin and an eligible target range. Instance, extension and dynamic dispatch, grammar-error files and files recognized as generated by suffix/header retain syntax evidence. Unmarked generated code cannot be detected reliably. The native Docker case must prove direct and imported top-level calls before any native binding claim is made.
  - Test: packages/engine/tests/context-dart-snapshot.test.ts :: maps UTF-16 query positions and accepts only exact unique local targets
  - Test: packages/engine/tests/context-dart-runtime.test.ts :: binds a direct and imported top-level call with all Dart source provenance
- AC5: An unavailable/untrusted runtime, excessive or malformed LSP output, a 15-second deadline, a 768-MiB container limit, or unconfirmed cleanup promotes no native binding and retains syntax evidence. A failure before analyzer initialization retains the private source view rather than assuming a killed Docker CLI proves the daemon did not create the container.
  - Test: packages/engine/tests/context-dart-runtime.test.ts :: treats stdout end as failure even when the analyzer exits successfully
  - Test: packages/engine/tests/context-dart-runtime.test.ts :: retains the source view when Docker cannot prove the owned container is absent
  - Test: packages/engine/tests/context-dart-runtime.test.ts :: reports a real bounded analyzer timeout without promoting a partial answer
- AC6: A repository without Dart files keeps the snapshot identity it had before Dart indexing existed, key for key, so its stored snapshots and plans stay valid. A repository with Dart files adds a Dart-only extractor version to its identity, and cached Dart syntax carries that version, so a change to Dart extraction re-parses only Dart files.
  - Test: packages/engine/tests/context.test.ts :: keeps snapshot identity unchanged for repositories without Dart files

## Security considerations

Repository content is untrusted. Syntax indexing only parses Dart text with the pinned WebAssembly grammar and downloads nothing. Dart files pass the same gitignore, exclusion, size and credential screening as every other file before they are parsed. The optional analyzer copies only checked Dart source and an engine-owned package config to a private disposable view. It never receives repository `analysis_options.yaml`, package dependencies, plugins or `.dart_tool`; it invokes the AOT analysis snapshot directly, not `dart`, `flutter`, pub or a build runner. A checked profile blocks process creation and the container has no network, a read-only root, bounded memory and a deadline. The profile cannot prevent later same-process exec, so the minimal operator-provisioned image and source-only view are also required. Image labels are not cryptographic attestation against a malicious Docker operator. A Docker failure may retain a private view for operator recovery. Native operation is pending exact-head CI evidence.

## Non-goals

The optional analyzer does not perform a full typecheck, resolve all Dart imports or calls, infer runtime dispatch, or execute repository code, pub or Flutter. It adds no Semgrep rules for Dart, since the pinned scanner image has no Dart rule set. The Dart and Flutter verification recipes in [verification images](../../docs/verification-images.md) are starting points, not tested images.
